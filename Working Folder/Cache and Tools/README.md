# Cache and Tools — Single home for project tooling and intermediate data

Generated artifacts (the xlsx and the dashboard html) live ONLY at the **git repo root**. Cache and Tools/ holds tooling, input data, and intermediate files — nothing user-facing is generated here. `rebuild.command` regenerates the xlsx fully and updates `index.html` in place by swapping its embedded JSON payload.

## Build flow

| Artifact | Where it lives | How it's regenerated |
|---|---|---|
| `index.html` | repo root | **Hybrid.** The embedded JSON payload (`<script id="data-payload">…</script>`) is rewritten in place by `rebuild.command` from the master CSV. CSS, JS, and slicer defaults (around lines ~165-166) are static and edited directly. |
| `G3-G7_Achievement_Data.xlsx` | repo root | **Generated** by `rebuild.command` from `Cache and Tools/extracted_data/master_demographics.csv`. |

There is no canonical-vs-deploy split anymore. The repo root is the single source of truth for both. (Earlier sessions had three copies — canonical inside the project payload, handoff in Working Folder/, deploy at root — that's gone.)

## Quick start

After editing `extracted_data/master_demographics.csv`:

```bash
cd "$HOME/Dev/Github/Achievement/Working Folder/Cache and Tools"
chmod +x rebuild.command   # one-time
./rebuild.command
```

This regenerates both `Achievement/G3-G7_Achievement_Data.xlsx` and the embedded JSON payload in `Achievement/index.html`. Done.

After editing the dashboard's UI, CSS, JS, or slicer defaults: edit `Achievement/index.html` directly. The build only touches the data payload.

## Why portable paths

Every script starts with:
```python
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from _paths import ...
```

`_paths.py` defines `HERE = this folder`, `WORKING_FOLDER = parent`, `REPO_ROOT = parent of that`. Move the whole repo anywhere on disk, rename `Achievement/`, run from any cwd — the build still works.
