# Working Folder

Tooling, cache, and session history for the Achievement dashboard project. The user-facing artifacts (`index.html`, `G3-G7_Achievement_Data.xlsx`) live at the **repo root**, not here.

## Layout

```
Achievement/                                  (git repo root — single source of truth)
├── index.html                                ← dashboard (static, hand-edited)
├── G3-G7_Achievement_Data.xlsx               ← xlsx (regenerated by rebuild.command)
├── LICENSE
└── Working Folder/                           ← THIS FOLDER
    ├── README.md                             ← this file
    ├── CHANGELOG.md                          ← audit trail of fixes
    ├── Cache and Tools/                      ← every script + cached/intermediate data
    │   ├── README.md                         ← detailed tool inventory
    │   ├── rebuild.command                   ← one-click xlsx rebuild
    │   ├── _paths.py                         ← shared path resolver
    │   ├── build_master_xlsx.py
    │   ├── patch_xlsx_in_place.py
    │   ├── refresh_demographics.py           ← OSPI Socrata pull (Bellevue)
    │   ├── extract_*.py / parse_*.py         ← per-state extractors
    │   ├── extracted_data/                   ← per-state + master CSVs
    │   ├── source_data/                      ← raw downloads (TSD subsets only)
    │   ├── spreadsheets/                     ← analytical artifacts
    │   └── project_docs/
    └── Prompts/                              ← per-prompt session capsules
```

## Quick start — rebuild the xlsx

After editing `Cache and Tools/extracted_data/master_demographics.csv`:

```bash
cd "$HOME/Dev/Github/Achievement/Working Folder/Cache and Tools"
chmod +x rebuild.command   # one-time
./rebuild.command
```

This regenerates both `Achievement/G3-G7_Achievement_Data.xlsx` and the embedded JSON payload in `Achievement/index.html` at the repo root. The dashboard's CSS, JS, and slicer defaults stay put — only the data payload is replaced. Edit `index.html` directly to change UI or defaults.

## What was wrong (Bellevue fix — 2026-04-28)

OSPI's Socrata API returns two District-level rows for the same `(year, subject, grade, subgroup)` cell:
- **SBAC** — Smarter Balanced, the regular assessment (N ≈ 1,300–1,500)
- **AIM** — alternate assessment for ~11–15 students with significant cognitive disabilities

`refresh_demographics.py` deduped on `(year, subject, grade, subgroup)` only, so AIM rows clobbered SBAC when AIM happened to sort first. Effect: 26 cells across 2022, 2024, and 2025 reported AIM proficiency in place of district proficiency. Fixed by filtering `testadministration == 'SBAC'` before dedup. See `CHANGELOG.md` for the per-cell before/after audit.

## Verification

After a rebuild you can spot-check any cell against OSPI directly. Example for 2025 Math G3 Bellevue All Students:

```bash
curl -s "https://data.wa.gov/resource/h5d9-vgwi.json?districtcode=17405&organizationlevel=District&testadministration=SBAC&testsubject=Math&gradelevel=03&studentgroup=All%20Students" | python3 -m json.tool
```

Expect `count_of_students_expected_1: "1345"`, `percent_consistent_grade: "69.4%"`.
